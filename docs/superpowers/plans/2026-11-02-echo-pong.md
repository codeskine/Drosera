# Echo Pong Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a second echo algorithm whose repeats bounce between left and right and stay dense and saturated, off by default.

**Architecture:** A new JUCE-free `PongDelay` sits beside `EchoDelay`, which does not change. `Engine` runs both and crossfades the wet signal, `DroseraCore` drives Drive and Tone through a third `ParameterRegistry`, and the ECHO tab gains three controls.

**Tech Stack:** C++17, JUCE 8.0.9, DaisySP `7f67768` (vendored), CMake with Ninja.

**Spec:** `docs/superpowers/specs/2026-11-02-echo-pong-design.md`

## Global Constraints

- With PONG off, renders stay byte-identical to `tools/hardware-comparison/reference/SHA256SUMS`. No new checksums. A failure is a bug.
- No allocation, locks or file access on the audio thread.
- `src/dsp/EchoDelay.h` and `third_party/` do not change. `tests/fixtures/state-baseline.bin` is not regenerated.
- Existing parameter IDs do not change, and parameter names stay in English everywhere.
- New parameters go at the end of the layout, in this order: `echopong`, `echodrive`, `echotone`. Do not reuse the removed `echotape`, `tapewow` or `tapeage`, which old saved states still hold.
- Do not add entries to `registry_` or to `DroseraCore::Param`. The registry iterates an `unordered_map`, so more entries could reorder its handlers.
- Work on a new branch, `echo-pong`, created from `three-string-polyphony`.
- Commit messages are one imperative sentence, as in `git log`, and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Feedback percentages are engine values, as the readout shows them: knob position × 150%.
